# nss/color_gui - Color Grading Explorer (PyQt6)

A desktop application that grades 16-bit TIFF images with the Lightroom Color Grading model in `nss/color_grading`.  The user grades manually
with the wheels or explores color harmonies through a 3x3 image grid.  Start it with `python color.py` from the repo root.

This package is the view layer only: no image maths lives here.  The grade itself is `nss.color_grading.Grading.apply`; the State Node type,
its defaults, the colour harmony maths and Random Shift are in `nss/color_explore` (`state.py`, `harmony.py`, `random_shift.py`).

## Data pipeline

Preserving the 16-bit data is the highest priority.

1. **Ingest:** read with `nss.tiff_file.TiffFile` (never OpenCV `imread`).  The array is float32 holding the values as stored (integer data divided
   by its full range, e.g. `/65535`; never min/max stretched), encoded in the file's own working space.  Only 3-channel RGB is accepted.
2. **Grade:** needs the file's embedded ICC profile; sRGB is never assumed.  Without a profile the image is shown ungraded and cannot be saved
   graded.  `Grading.apply(img, icc, ...)` returns the same encoding and dtype.
3. **Preview:** a copy downsampled to at most 1200 px (`nss.image_utils.downsample_image`) is graded for the screen and mapped to 8-bit for
   display.  Never overwrite the master array.
4. **Save:** the full-resolution master is graded and written with its original bit depth and ICC profile.

## State and undo

* Parameter-based state: a State Node is a dictionary of settings (`shadow_hue`, `shadow_sat` 0..1, `shadow_light` -1..1, the same for
  `midtone_*`, `highlight_*`, `global_*`, plus `blending` 0..1, `balance` -1..1, `rotation` in degrees, and the mixer's `mixer_hue` /
  `mixer_sat` / `mixer_lum`).  Never store images in history.
* `state_manager.py` keeps undo/redo stacks of snapshots gathered from the registered widgets (each has a unique `STATE_KEY`).  Snapshots are
  pushed on discrete actions (slider release, wheel release, reset, preset load); keys missing from older snapshots take their defaults.
* `grading_state.py` maps a State Node to `Grading.apply` arguments (sat / light x100, blending x100, balance x100); Rotation is added to every
  wheel's hue, Global included.
* `presets.py` saves / loads JSON presets (`{"version": 1, "state": {...}}`); missing keys default, unknown keys are ignored.

## UI layout

* Color Harmony panel (`harmony_panel.py`, between Explore & Harmony and the Color Mixer): see Color Harmony below.
* Color Mixer panel (`mixer_panel.py`, between Color Harmony and the wheel tabs): Hue, Saturation and Luminance tabs, each with a full-width
  -100..100 slider per band (Red ... Magenta) under its name and value (double-click a slider to reset, Reset Mixer zeroes all 24).
  Tracks are painted like the wheels' Hue slider: Hue = the hues the band moves to at -100 .. +100 (`bands.hue_shift`), Saturation = grey to
  band colour, Luminance = dark to light band colour.  A band hue (linear ProPhoto) is shown as the wheel rim colour with the same screen hue.  `nss.color_mixer.ColorMixer.apply` runs before the grade; its values travel in the state as `mixer_hue` /
  `mixer_sat` / `mixer_lum` (snapshot key `color_mixer`) and are not saved in presets.
* Left: the single preview, or the 3x3 explore grid when Explore Mode is on.  Clicking an outer cell promotes it to the centre and generates
  8 new mutations around it.
* Right panel: Explore & Harmony controls (Mixer / Grading checkboxes, Explore Mode, Random Shift, Variation Strength); Color Harmony; the Color Mixer; the Color Grading group:
  four wheel tabs, Shadows, Midtones, Highlights and Global, each with a colour wheel, Hue / Sat / Luma sliders (double-click a label to reset),
  then the master controls (Blending, Balance, Rotation, Reset Grading).
* File menu: Open, Recent Directories, Save As, Save Preset, Load Preset.

## Colour wheels

All wheel geometry and painting lives in `wheel_lut.py` (one place to change it):

* **Hue = screen angle**, 0 at 3 o'clock, counter-clockwise, as on Lightroom's wheel (its handle for hue H sits at angle H + 0.04 degrees).
  `hue_from_angle` / `angle_from_hue`; the number sent to `Grading.apply` is that angle.  Rotation is added to it for drawing.
* **Saturation radius:** Sat 100 at `SAT_FULL_RADIUS` = 0.907 of the painted radius, linear to Sat 0 at the centre; clicks beyond clamp to
  Sat 100.  The painted disc extends to 1.0.
* **Painting** is Lightroom's, measured: the rim colour per degree (warped, e.g. green is painted near 154 degrees) blended to a centre grey
  of 242 along a measured profile.  The tables are in `wheel_lut_tables.py`, GENERATED by `python -m tools.make_wheel_tables` from
  `tests/test_data/lr_wheel_<H>.png`; never edit them by hand.  `python -m tools.validate_wheel_lut out.png` compares the painting with
  the screenshots (mean CIELAB dE 2.6).
* The Hue sliders show pure hue HSV (h, 1, 1) over 0..360, the colour Lightroom shows beside the wheel.

## Random Shift and Explore Mode

Random Shift moves the sliders at random toward the Color Harmony samples (harmony modes are chosen only in Color Harmony).  The maths is
`random_shift` in `nss/color_explore/random_shift.py`; strength = Variation Strength / 100 (default 5%), every r is uniform in [-1, 1].

* **Mixer** (checkbox): each band's weight is the largest, over the samples, of its band weight at the sample's mixer hue
  (`bands.slider_at`), damped for grey or dark displayed colours (HSV sat and value below 0.1); its Hue, Sat and Lum get r * strength * 100 * weight.
* **Grading** (checkbox): each sample's displayed colour goes to the tonal wheel whose mask is strongest at its luminance (current Balance and
  Blending, `tonal_zone`).  A wheel with samples gets hue = circular median of their wheel hues (less Rotation) + r * strength * 360, sat = their
  median HSV sat + r * strength, light = its own light + r * strength; wheels without samples, Global, Blending and Balance are kept.
* The button is enabled only with a sample and a checkbox checked.  Each click starts from the current sliders and is one undo step; in Explore
  Mode it re-rolls the 8 outer images instead.  Explore Mode surrounds the centre with 8 independent shifts of it, or shows the centre only
  (with a status message) when Random Shift is not ready.

## Color Harmony

Checks sampled image colours against harmony wedges and shows how the Color Mixer's Hue sliders move them.  The maths is outside this package:
`nss.color_mixer.hue_remap` (the mixer's hue mapping f as a 360-point table and its inverse) and `nss.color_explore.harmony` (modes, best fit, wedges).

* **Wheel axis** is the Color Grading wheel's angle.  A mixer hue h (hexagon hue of linear ProPhoto) sits at g(h), the angle whose rim colour
  has the same screen hue (`MIXER_TO_WHEEL`, the match `band_color` makes, interpolated).  The mixer's hue mapping f (re-measured on every Hue
  slider change through `ColorMixer._linear`) becomes F = g . f . g^-1 on wheel angles; angle a is painted with the grading wheel's colour at
  F(a), so with neutral sliders the harmony wheel is the Color Grading wheel.  The colours and wedges warp while the sample markers stay.
* **Samples** (eyedropper button; Esc or a second click stops; at most 16, numbered with the lowest free slot): the colour is the 5x5 median of
  the displayed preview; the input hue is read from the pre-mixer proxy at the same pixel, because the grade after the mixer also moves hues.
  Each sample appears as a circle on the preview, a marker outside the wheel rim and a patch in the 2 x 8 grid; left click opens the info popup
  (original and current colour), right click offers Remove.
* **Wedges** are target OUTPUT wheel angles (`HARMONY_MODES` in `nss/color_explore/harmony.py`), drawn at the angles F maps into them (several arcs where
  F folds over).  A sample whose marker lies inside its nearest wedge is in harmony; otherwise an arrow points to that wedge's nearest edge.
* Choosing a mode fits the Wedge Rotation (0.5 degree grid search) to the samples' current output angles; the slider then rotates all wedges.
* Snapshot key `color_harmony`: samples, mode, rotation (the eyedropper state is not saved).  Reset Harmony never touches the mixer; opening a
  file clears the samples and keeps mode and rotation.

## Threads

No grading runs on the GUI thread.  `PreviewWorker` grades the single preview (while one runs, only the newest request is kept and starts when
it finishes); `GradingWorker` grades the 3x3 grid; `SaveWorker` grades and writes the full-resolution file.  Slider drags are debounced
(`RENDER_DEBOUNCE_MS`); a release renders immediately.  Closing the window waits for running workers.

While a Color Mixer slider is held, the preview renders a smaller copy (`DRAG_PREVIEW_DIM`); the release renders the 1200 px proxy.
`MixerCache` keeps the last mixer result per preview image, so grading-only changes and the 3x3 grid do not re-run the mixer; Save runs the
mixer on the full image uncached.

## Lightroom

`python color.py --lightroom <request file>` is started by the Lightroom plug-in (`plugin/`; file format in `plugin/lr_bridge.py`).  The
request's TIFF is loaded and the Color Mixer, the four wheels (Global included), Blending and Balance start at its Lightroom values (one undo
step after the neutral load).  Apply to Lightroom (status bar) writes them to the result file, hues with Rotation added as graded, and
exits 0; closing the window any other way exits 1 and writes nothing.

## Tests

`<module>_test.py` next to each module.  Run headless with `QT_QPA_PLATFORM=offscreen`.  A test that holds a `MainWindow` must keep the
`QApplication` alive for the whole test and let render threads finish before the window is destroyed (see `main_window_test.py`).
